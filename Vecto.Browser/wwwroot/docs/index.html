01

QUICK START

Cara menggunakan DikaTrace

Konversi pertama tidak memerlukan konfigurasi khusus. Gunakan pengaturan otomatis terlebih dahulu, lalu sesuaikan bila ada detail yang perlu ditingkatkan.

  1. 01

    Buka studio dan pilih gambar

    Masuk ke DikaTrace Studio, lalu pilih file PNG, JPG/JPEG, WebP, atau BMP. Batas input saat ini 20 MB dan 8 megapiksel. Pratinjau gambar asli akan muncul.

  2. 02

    Tentukan susunan bentuk

    Pilih Berdampingan (Planar) untuk region yang berbagi batas, atau Bertumpuk (Stacked) untuk gambar dengan bentuk/lapisan saling menutupi, seperti logo maskot.

  3. 03

    Atur jenis gambar dan detail

    Mulailah dengan Jenis gambar: Otomatis dan Detail: Sedang. Untuk ilustrasi antialias yang rumit, coba Ilustrasi halus + Tinggi.

  4. 04

    Buat SVG

    Tekan Buat SVG. DikaTrace akan menyiapkan piksel, mengelompokkan warna, membangun region dan batas, memasang kurva, lalu menghasilkan dokumen SVG.

  5. 05

    Periksa hasil dan metadata

    Gunakan tombol Asli, SVG, dan Bandingkan. Dalam mode Bandingkan, seret pembatas Before / After pada gambar: sisi kiri raster asli, sisi kanan SVG. Geser gambar untuk pan, cubit dua jari di HP atau putar roda mouse untuk zoom hingga 1000× dari ukuran pas pratinjau. Tombol 1000×, +/−, Reset, dan slider zoom juga tersedia. Buka panel metadata untuk melihat jumlah path dan segmen.

  6. 06

    Unduh dan edit

    Tekan Unduh SVG. File dapat dibuka di aplikasi editor yang mendukung SVG. Jika unduhan tidak berjalan di browser tertentu, gunakan opsi buka SVG lalu simpan dari browser.

Tip: simpan satu hasil dengan semua fitur eksperimen OFF sebagai baseline. Ini berguna saat membandingkan hasil optimasi baru.

03

DI BALIK ENGINE

Mekanisme pemrosesan gambar

DikaTrace menggunakan pipeline vektorisasi deterministik berbasis analisis piksel dan geometri. Engine tidak sekadar membungkus foto menjadi SVG, tetapi membentuk region warna, menelusuri batasnya, dan menyusun path vektor baru.

RASTER→PALET→REGION→GEOMETRI→SVG
01

Decoding dan pembacaan piksel

File diubah menjadi data piksel RGBA beserta ukuran aslinya. PNG dan JPEG yang didukung memakai decoder C#; format atau variasi yang tidak didukung dapat memakai decoder browser. Pemeriksaan dimensi membatasi beban memori.

02

Persiapan piksel

Tahap penyiapan mengevaluasi noise dan variasi warna di bidang rata. Pada input yang memenuhi kriteria, perbedaan warna kecil dapat dibersihkan. Tepi berkontras tinggi, dimensi dan transparansi diprioritaskan agar tidak berubah. Foto dan gradasi yang tidak cocok dapat dilewatkan.

03

Estimasi palet

Engine menganalisis warna dominan dan area warna yang relatif stabil. Untuk gambar non-exact, pusat warna dihitung melalui pengelompokan di ruang persepsi Oklab, dengan inisialisasi k-means++. Pusat warna yang terlalu dekat dapat digabung sesuai profil.

04

Segmentasi dan koreksi fringe

Setiap piksel buram/solid diberi label warna. Label yang berdekatan membentuk komponen region. Sistem mempertimbangkan tepian antialias, serpihan area kecil, dan indikasi noise JPEG berdasarkan profil gambar, agar batas bentuk tidak dipenuhi fragmen yang tidak perlu.

05

Boundary graph dengan shared-edge

Engine menelusuri batas antarregion sebagai rantai geometri bersama. Ketika dua region bertetangga, batas yang sama dapat digunakan dengan arah berlawanan. Ini menjaga konsistensi tepi sebelum tahap fitting dan mengurangi risiko celah akibat dua batas yang dihitung terpisah.

06

Sudut, subpiksel, dan fitting Bézier

Kontur diperiksa untuk menemukan sudut struktural. Titik yang aman dihaluskan, lalu posisi tepi dapat disesuaikan secara subpiksel. Kurva kubik Bézier dipasang dengan toleransi berdasarkan tingkat Detail; optimasi node membandingkan kandidat penyederhanaan sambil menjaga sudut yang dilindungi.

07

Penyusunan region menjadi bentuk

Dalam Planar, region mempertahankan struktur batas berdampingan. Dalam Stacked, engine memperhitungkan urutan gambar dan penutupan region tertentu untuk membentuk lapisan yang tampak. Susunan ini berdasarkan geometri—bukan pemahaman semantik seperti mengenali “mata” atau “rambut”.

08

Penulisan SVG dan ekspor

Dokumen akhir ditulis sebagai SVG 1.1, menggunakan path langsung, warna isi solid, koordinat dua desimal, dan instruksi seperti M, L, C, Z. File dibentuk dalam browser dan disediakan melalui tautan unduh.

Penting: kualitas SVG ditentukan oleh akurasi palet, segmentasi, kontur, dan kurva secara bersama-sama. Jumlah node atau ukuran file yang lebih kecil bukan bukti otomatis bahwa hasilnya lebih akurat.
04

STRUKTUR SVG

Planar dibandingkan Stacked

BERDAMPINGAN

Planar

Region dipertahankan sebagai bagian-bagian yang bertemu pada batas bersama. Cocok untuk bidang warna datar atau saat konsistensi tepi antarregion menjadi prioritas.

BERTUMPUK

Stacked

Region disusun dengan urutan gambar sehingga beberapa bentuk bisa berada di depan atau di belakang bentuk lain. Cocok untuk maskot dan ilustrasi berlapis.

Keduanya menghasilkan path SVG, bukan lapisan bitmap. Stacked tidak secara otomatis mampu menebak bagian objek yang sepenuhnya tersembunyi.

05

FITUR LANJUTAN

Eksperimen kualitas

Fitur berikut tersedia sebagai opsi uji. Semuanya nonaktif secara default agar hasil standar tidak berubah tanpa keputusan pengguna.

Local Edge V3

Engine koreksi tepi

Menguji penyesuaian kecil titik tepi yang memiliki bukti perubahan coverage. Pilih Bandingkan A/B untuk menghasilkan Original dan V3 dengan parameter identik.

Region Merge V1

Pengaturan lanjutan

Mencoba menyatukan komponen region kecil hanya jika kedekatan warna, tetangga, dan kondisi topologi mendukung.

Anti-alias Aware Segmentation V1

Pengaturan lanjutan

Menganalisis pita warna transisi tipis agar tidak menjadi region terpisah tanpa alasan kuat. Beberapa kategori input secara sengaja dilewatkan.

Stacked Layer Reasoning V1

Khusus mode Stacked

Mencoba mengemas path sewarna yang boleh berdampingan dalam urutan gambar. Jika pemeriksaan raster menemukan perubahan, kandidat dapat dibatalkan dan hasil lama digunakan.

Perlu diketahui: fitur eksperimen tidak dijamin memperbaiki semua gambar. Uji satu per satu terhadap baseline sebelum menggabungkannya. Tombol A/B Original–V3 hanya membandingkan V3, bukan otomatis seluruh opsi eksperimen.

ANALISIS OUTPUT

Memahami metadata & perbandingan A/B

Setelah SVG dibuat, bagian Metadata SVG menampilkan statistik dokumen yang dihasilkan. Data ini berguna untuk menilai ukuran, susunan geometri, dan perubahan eksperimen.

Path / SubpathElemen dan kontur dalam dokumen vektor.
Garis L / Kurva CJumlah perintah geometri lurus dan Bézier.
Warna HEXPalet warna fill yang digunakan SVG.
Node & OptimasiJumlah node fitting dan hasil optimasi.
Ukuran & ViewBoxUkuran byte serta sistem koordinat SVG.
Waktu tracingDurasi tahap palet, segmentasi, batas, fitting.

Mode A/B Original vs V3 menggunakan pembatas Before / After yang sama untuk membandingkan dua SVG pada posisi dan zoom identik. Zoom hingga 1000× tidak mengulang engine tracing: SVG diperbesar melalui viewBox agar tetap tajam, sementara JPG/PNG digambar ulang hanya pada area pratinjau, bukan sebagai tekstur raksasa. Kamera dikunci pada batas gambar untuk menghindari area kosong saat digeser. Ketajaman JPG/PNG tetap dibatasi resolusi piksel asli dan performa bergantung pada kemampuan browser/perangkat. Mode A/B juga memperlihatkan MAE RGB, IoU mask gelap, dan SSIM luminans lokal 8×8 pada pratinjau berukuran terbatas. SSIM tersebut bukan perhitungan Gaussian SSIM standar. IoU mask hitam-putih juga tidak dapat menjelaskan semua perbedaan ilustrasi berwarna.

07

BEST PRACTICES

Cara mendapatkan SVG lebih rapi

01

Gunakan input resolusi baik. Logo PNG dengan warna solid umumnya lebih mudah diproses dibanding JPG yang memiliki artefak kompresi.

02

Jangan selalu mengejar banyak warna. Warna terlalu banyak dapat menambah fragmen dan path; terlalu sedikit dapat menghilangkan aksen kecil.

03

Periksa area paling sulit. Perbesar ujung rambut/bulu, garis tebal-tipis, lingkaran, mata, gigi, dan sudut kecil.

04

Bandingkan di pengaturan yang sama. Gunakan gambar, detail, jenis gambar, dan seed identik ketika menguji Original versus fitur eksperimen.

05

Nilai bentuk dan kemudahan edit. SVG berukuran lebih kecil atau jumlah path sedikit tetap bisa memiliki hasil visual yang lebih buruk.

08

TROUBLESHOOTING

Pertanyaan yang sering muncul

Kenapa hasil SVG terlihat patah atau tidak halus?

Coba aktifkan Kurva Bézier, naikkan Detail, dan periksa apakah input terlalu kecil atau terkompresi. Jangan langsung mengaktifkan semua eksperimen sekaligus.

Kenapa warna kecil seperti mata atau aksen hilang?

Palet otomatis mengutamakan warna yang memiliki dukungan cukup pada sumber. Warna dengan area sangat kecil atau tercampur noise bisa terwakili oleh warna lain. DikaTrace mencoba melindungi warna solid yang memang ada di sumber. Jika masih hilang, pada Batas warna SVG pilih 8 atau 12 warna, lalu tekan Buat SVG ulang. Coba input PNG bersih dan bandingkan mode Ilustrasi halus/Tinggi; tidak ada jaminan setiap warna kecil dipertahankan.

Kenapa SVG punya banyak path atau ukuran besar?

Gambar rumit memiliki lebih banyak region dan batas. Jumlah path juga dipengaruhi mode Planar/Stacked. Lihat angka segmen L/C dan hasil render, bukan hanya ukuran berkas.

Kenapa tombol unduh tidak bekerja di HP?

Coba tautan cadangan Buka SVG lalu simpan lewat browser. Beberapa WebView membatasi unduhan dari blob URL. Browser Chrome/Firefox terbaru biasanya lebih kompatibel.

Kenapa proses terasa lama atau tab berhenti merespons?

Tracing dan perakitan SVG mengonsumsi CPU dan memori perangkat yang digunakan. Coba input lebih kecil, Detail Sedang, atau kurangi kompleksitas gambar. Pemrosesan lokal tidak otomatis berarti instan.

Apakah hasil Stacked selalu lebih bagus daripada Planar?

Tidak. Stacked mengubah struktur tumpukan path dan mungkin lebih cocok untuk gambar tertentu, tetapi bentuk yang sulit tetap perlu dibandingkan secara visual.

Bisakah SVG langsung menjadi file Alight Motion?

DikaTrace mengekspor SVG standar. Konversi ke format lain perlu aplikasi atau alat konversi yang mendukung SVG; proses tersebut tidak termasuk ekspor SVG bawaan di halaman ini.

TRANSPARANSI TEKNIS

Privasi, lingkungan, dan batasan

Diproses di perangkat

Tracing berjalan dengan C# di Blazor WebAssembly (.NET 8). Gambar yang dipilih tidak sengaja dikirim ke server untuk diproses. Halaman statis dan aset aplikasi tetap dimuat melalui hosting web.

Batas input

File yang dipilih dibatasi 20 MB / 8 MP. Browser dan RAM perangkat dapat menambah keterbatasan praktis.

Fidelity

SVG adalah representasi vektor hasil perkiraan dari piksel. Bentuk sangat rumit, gradasi halus, foto, dan aksen kecil dapat berbeda dari gambar asal.
